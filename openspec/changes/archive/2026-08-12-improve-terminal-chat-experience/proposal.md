## Why

Weave 已能完成多轮流式对话，但当前纯文本渲染、按逻辑行滚动和手绘光标使 Markdown 回答难以阅读，CMD 中文输入法候选窗位置错误，鼠标滚轮也无法查看上文。生成期间虽然允许编辑草稿，却缺少可连续表达补充要求的排队机制，因此需要在进入工具调用等更复杂能力前先稳定终端对话体验。

## What Changes

- 将 assistant 回答改为渐进式 Markdown 渲染：完整块立即呈现，未闭合尾段暂按纯文本显示，完成时执行最终规范化渲染。
- 支持标题、强调、删除线、列表、任务列表、引用、行内代码、围栏代码块、链接、分隔线和表格；表格在窄终端降级为逐行键值布局，代码块提供安全语法高亮和带续行标记的视觉折行。
- 按终端实际显示行而非仅按换行符计算对话视口、输入框高度、Unicode 宽度和滚动偏移，覆盖中文、Emoji、组合字符及窗口尺寸变化。
- 接入鼠标滚轮并保持对话区为唯一滚动区域；离开底部后暂停自动跟随，显示新增行数，并支持返回底部。
- 移除手绘光标，使用终端原生光标并将其定位到真实插入点，使 CMD 中文输入法候选窗跟随输入位置。
- 增加生成期间的消息队列：多次提交按顺序用空行合并，当前回答正常完成后自动发送；错误、中断、截断或拒答时暂停并等待显式恢复。
- 提供队列数量与最新消息预览、`Ctrl+Z` 撤回队尾、未提交草稿隔离以及退出丢失提示。
- 将 Windows 11 CMD 加入正式终端验收范围。
- 不在本次变更中增加输入历史、斜杠命令、会话持久化或并发 turn。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `terminal-chat`: 修改终端回答渲染、显示行布局、滚轮与跟随、真实光标、生成期消息队列以及跨终端验收要求。

## Impact

- 主要影响 `src/interaction/` 的转录渲染、布局、视口、输入模型、终端控制和 TUI 状态管理。
- 需要引入或实现 Markdown 解析、安全终端样式、Unicode 显示宽度、鼠标事件与语法高亮能力；具体依赖在设计阶段确定。
- `ConversationController` 继续保持单活动 turn，队列在交互层串行调用现有提交端口，不改变 LLM 协议适配器和持久化边界。
- 单元、集成和终端 E2E 需要扩展，新增 Windows 11 CMD 验收，同时保留 Windows Terminal/PowerShell 与 WSL 覆盖。
